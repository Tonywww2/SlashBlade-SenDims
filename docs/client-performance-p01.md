# 客户端性能 P0 / P1 实现

记录客户端性能 P0 与 P1 的实现和实测结论。

## 行为与边界

- **P0 阴影血条**：Neat `hookRender` 的 HEAD 查询 Iris API 的动态阴影状态，在阴影通道跳过整个血条与护甲 UI。只在首次渲染时解析可选 API，并绑定 MethodHandle；普通通道、实体本身和实体阴影不受影响。缺少 Oculus 或 API 失败时保守保留 Neat 原行为。
- **P1 血条缓存**：每线程复用 DecimalFormat，按格式字符串及 FORMAT Locale 失效；128 槽数值文字缓存；最多 1024 条、单条最多 256 字符的宽度缓存；最多 16 个只交给渲染器的图标 ItemStack；0–256 护甲文字缓存；颜色按配置字符串更新。资源/语言重载递增 epoch，下一次访问丢弃缓存；Font 替换也清除宽度缓存。没有缓存实体引用、生命值或名称，因此实体状态变化立即反映。护甲替换尾部保留 Neat 41 的两个外层 pop，并用 finally 配平内部 push/pop。
- **P1 可选精简**：新增 `slashblade_sendims.toml`，`performance.neat.healthBars` 可选 `ALL`（默认）、`DAMAGED_OR_TARGETED`、`TARGETED`；`compactHealthText=false` 默认保留最大生命和百分比字段，开启后隐藏二者；`attributeIcons=true` 默认保留生物类型图标。既有 Neat 配置仍生效，护甲继续受 Neat 的 `showArmor` 控制。没有自动降低画质或改变默认可见血条。
- **P1 兼容查询**：仅在 FMLLoadComplete 发布已加载模组 ID/版本的不可变快照，DeRenderPatcher 后续查询不再执行反射。加载早期沿用上游逻辑，未知 ID 不写入缓存。可选模组仍通过 Mixin 插件的目标类资源检查跳过；光影当前开关从不当作静态模组状态缓存。
- **P1 模型遍历**：每个 ModelPart 自己持有最多 512 节点的前序拓扑快照；每次验证 children map 的身份、大小、节点身份及顺序，仅返回一个流，不缓存动画姿态。检测到拓扑变动后，本模型回退原遍历直到资源重载；自定义 ModelPart 子类、循环和超大拓扑直接回退。资源重载作 epoch 失效，新旧模型之间没有全局强引用缓存。修改流创建前的拓扑可立即被检测；如外部代码在创建流后、消费期间修改模型树，仍应遵守模型渲染线程约束。
- **P1 流体分配**：将 Forge 流体扫描的 Object2ObjectArrayMap 改为零容量起步、遇到实际流体再自动扩容。保留扫描边界、predicate、流体高度、迭代顺序、浮力/流速/推动与实际物理逻辑，客户端和服务端均适用；不跳过干燥区域检查、不缓存世界流体状态。

## 验证入口

全部代码完成后运行 `gradlew.bat --offline build clientPerformanceTest`。
`clientPerformanceTest` 覆盖前序顺序、即时动画、嵌套/同大小替换、重排/增删/map 替换、动态/循环/大模型回退、数字格式及语言切换、可选模组存在/缺失和快照不可变性，以及流体表扩容与顺序一致性。

游戏简单回归沿用独立测试存档，玩家与实体位于 Y=310，对照普通及 Complementary Unbound 光影，检查持刀、300 生物、粒子、护甲血条与资源重载。短测试仅用于检查集成、回归和初步帧时间变化，不替代原先完整的多轮测量。

## 未扩大范围

不涉及 P2/P3 的堆参数、光影画质、资源缩小、动态资源加载、新增遮挡剔除或光效 LOD。未删除项目中原有的历史构建、用户代码或模型资源。

## 本轮完成后的简单测试（2026-10-14）

`gradlew.bat --offline build clientPerformanceTest` 构建成功；新增 2112 项边界检查及原有 Leader API、End 岛兼容与世界树几何检查全部通过。

通过 PrismLauncher 命令行启动，独立复制存档测试。共完成 12 个场景、32713 帧、144.1 秒场景测量；141 条测量期遥测全部为 Y=310、1920×1080、窗口前台且未最小化。每个场景只测一轮 12 秒；初始普通空场景受启动长 tick 影响，不用于收益对比。

原数据为先前报告的多轮结果，本轮是完成后的短回归，不能把差值当作受控重复 A/B 的最终提升比例。默认仍显示满血生物、最大生命、百分比与属性图标；测试未通过隐藏血条或降低光影画质提高帧数。

游戏内额外断言通过：加载完成后 Oculus/ImmediatelyFast 存在性、DeRenderPatcher 未知 ID 返回 false、真实 ModelPart 前序遍历、姿态即时变化、同大小子节点替换及后续动态回退。完整资源重载完成，epoch 从 1 变为 2，随后确认使用 IrisRenderingPipeline；截图检查普通血条、护甲图标、刀、粒子、圣剑光效与实体阴影保留。

光影的两个密集组合场景中，1159 个 Render thread Java 执行样本里没有再观察到 Neat 与 Iris ShadowRenderer 共存路径；其中仍有 280 个阴影路径样本和 305 个 Neat 常规绘制样本。采样支持阴影 UI 重复绘制已被去除，但不代表 API 检查绝对零开销。

普通组合场景 Render thread 的 JFR 分配权重折算约从原两轮平均 0.85 GiB/s 降到本轮 0.44 GiB/s。原本突出的 ModelPart 流式遍历、DeRenderPatcher 反射、客户端流体预分配不再出现在该场景的前 50 个分配路径中。权重是统计分配量估计，不能当作常驻内存节省；固定 12 GiB 堆设置没有改变，本次短测不宣称常驻内存下降。

验证期 GC 暂停最大 0.1534 ms。光影切换和资源重载阶段在本包中共耗时约 122 秒并出现堆压力提示，最终正常完成；重载耗时不计入场景帧率。未进行移除 Oculus/ImmediatelyFast 后的完整启动矩阵，也未做所有自定义流体的玩法回归。
